# 产出物与临时脚本的落点

两类文件各有固定落点，写之前先认清楚写的是哪一类，再决定路径：

| 类别 | 认哪些文件 | 写到哪里 |
| --- | --- | --- |
| 交付物 | `.docx`、`.doc`、`.xlsx`、`.xls`、`.pptx`、`.ppt`、`.pdf`、`.csv`、`.png`、`.jpg`、`.jpeg`、`.svg` | 产出物根目录 |
| 临时脚本 | `.ps1`、`.psm1`、`.sh`、`.py`、`.sql`、`.bat`、`.cmd` | 脚本根目录 |

默认是两个家目录下的分层目录，具体值以插件配置为准（设置 → 插件 里可改）：

```
产出物：D:\Media Files\个人\TEMP\docs\<项目名称>\<年-月-日>\<文件名>.<后缀>
脚本：  D:\Media Files\个人\TEMP\scripts\<工作区>\<年-月-日>\<文件名>.<后缀>
```

`<项目管理>` 用能看出内容的短名，`<年-月-日>` 用当天日期（如 `2026-11-08`）。目录不存在就直接建，不要求用户先建。

## 规矩

- 工作副本、仓库目录里只放源码，不放交付物，也不放一次性脚本。写完就留在 TEMP 下，不再往仓库里拷。
- 同一天、同一主题的内容合并成一个文件，不要碎成一堆小文件。
- 脚本文件名要能看出用途，别用 `test.py`、`tmp.ps1` 这种名字。
- 用户明确指定了路径时按用户的来；这时如果被守卫拦下，先跟用户确认那个目录是不是该加进 `extraRoots`，不要自己往里塞。
- 判定只在写入这一刻做：编辑仓库里的 `.js`、`.md` 源码不受影响，守卫只认上表那两类后缀。

## 被拦了怎么办

守卫返回的提示里有目标路径和允许的根目录。按下面顺序处理，不要绕过：

1. 确认写的是交付物还是脚本，改到对应根目录下，重新执行。
2. 目标确实必须留在原位（例如工作副本里本来就有这个文件），把那个根目录加进插件配置的 `extraRoots`，再重试。
3. 不要为了绕开拦截改用别的写入手段：重定向、`Out-File`、`Set-Content`、`tee`、`edit` 工具都在守卫的检查范围内，换写法只会再被拦一次。
